# 결정 기록 (ADR)

설계 · 기술 선택과 **이유**를 남긴다. 에이전트는 기존 결정을 따르고, 바꿔야 하면 사용자에게 묻고 새 기록을 추가한다.

- 파일: `NNNN-<주제>.md` (번호는 늘리기만 한다). 처음 설계는 `project-design` 스킬이 `0001-initial-design.md` 로 만든다.
- 결정을 뒤집으면 기존 파일은 지우지 않고 `상태: 대체됨 → NNNN` 으로 바꾼다.
- 결정의 결과로 생긴 규칙은 `.harness/rules/` 에, 요약 한 줄은 `project.md` "핵심 결정" 표에 둔다.

## 형식

```markdown
# NNNN. <제목>

- 날짜: YYYY-MM-DD
- 상태: 채택 | 대체됨 → NNNN

## 배경
무엇을 정해야 했나 · 제약

## 결정
| 주제 | 선택 | 고려한 대안 | 이유 |
|---|---|---|---|

## 결과
- 생긴 규칙 · 설정 (`.harness/rules/…`, `config.json` …)
- 감수하는 단점
```
